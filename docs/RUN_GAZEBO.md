# Running PX4 with Gazebo on Windows (WSL2)

These notes record what was done by hand on 2026-11-20 and the problems met. They were not tested on a second machine. Where a step is a guess it says so. For anything else check the PX4 documentation at docs.px4.io.

## Setup

1. Use a separate WSL2 distro with a clean Ubuntu 24.04. PX4's setup script changes the system and should not run in a distro that already holds other work (for example a ROS 2 workspace).
2. Move the distro to a drive with room (about 10 GB for PX4 and Gazebo):
   ```
   wsl --export Ubuntu-24.04 E:\wsl\ubuntu-clean.tar
   wsl --unregister Ubuntu-24.04
   wsl --import PX4-Sim E:\wsl\PX4-Sim E:\wsl\ubuntu-clean.tar
   ```
   Check `wsl -l -v` first. If a distro with that name already exists it holds someone's work, so do not export and unregister it by accident.
3. Inside the distro, work in the Linux home directory, not under `/mnt/c`:
   ```
   cd ~
   git clone https://github.com/PX4/PX4-Autopilot.git --recursive
   cd PX4-Autopilot && git checkout v1.17.0 && git submodule update --init --recursive
   bash ./Tools/setup/ubuntu.sh
   ```
   Then close and reopen the distro.
4. `make px4_sitl gz_rc_cessna` (fixed-wing) or `make px4_sitl gz_x500` (quadcopter). The first build takes a long time.

## Problems met

- **Protobuf error** (`#error This file was generated by a newer version of protoc`). The compile line contained `-isystem /mnt/c/.../anaconda3/Library/include`. WSL had added the Windows PATH, and the build found Anaconda's protobuf 5.x headers instead of Ubuntu's 3.21. Fix: stop WSL appending the Windows PATH, by adding this to `/etc/wsl.conf` inside the distro (append, do not overwrite):
  ```
  [interop]
  appendWindowsPath=false
  ```
  Then `wsl --shutdown` from PowerShell and reopen. Check with `echo $PATH | tr ':' '\n' | grep -c /mnt/c`, which should print 0.
- **`make distclean` empties the submodules**, including `Tools/simulation/gz`, and then the `gz_*` targets disappear (`ninja: error: unknown target`). Run `git submodule update --init --recursive` and delete `build/px4_sitl_default` so CMake configures again.
- **Arming denied, "No connection to the GCS".** In the simulator without a ground-control app, `param set NAV_DLL_ACT 0` clears it. The value does not survive a restart.
- **Arming denied after a flip.** A plane that tipped over on landing fails the attitude checks. Restart the simulator.
- **The Gazebo window can hang on exit.** Close it by hand and run `wsl --terminate PX4-Sim` from PowerShell. Files stay.
- **Entity Tree and camera.** The plane sometimes did not show in the Gazebo Entity Tree even though PX4 flew it. Cause unknown. The simulation also slowed to 74 to 78 percent speed. Checking the flight with `listener vehicle_local_position 1` in the PX4 shell works without the window.
- **IMU timestamp errors** (`vehicle_imu ... timestamp error`) appeared in bursts. The flights carried on. Cause not investigated.

## Flying by hand

```
pxh> param set NAV_DLL_ACT 0
pxh> commander check
pxh> commander takeoff
```

Fixed-wing takeoff goes to 30 m by default and then circles. To cut the engine use the parameters, not `failure motor off`:

```
pxh> param set FW_THR_MIN 0
pxh> param set FW_THR_MAX 0
pxh> listener vehicle_local_position 1
```

`z` is negative upward, so about -30 means 30 m up. Do not use `commander land` on the plane: it can tip over. Let the fault flight end by itself or run `shutdown`.
